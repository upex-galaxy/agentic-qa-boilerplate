The Naming Codex

Every test artifact in this framework has one exact name shape. This is the single source of truth — from a TMS test case to a KATA component, a branch, a folder. Learn the shape once; read any artifact's intent at a glance.

Read these five first — everything else derives from them

The Five Laws

1 · should = the case

Every individual test case (TMS TC, ATC, E2E, integration) asserts behavior with should. Outcome-first, never "Validate".

2 · Validate = the group

Validate <feature> names only the grouping layer — a Xray Test Set summary or a code describe(). Never an individual case.

3 · Prefix = the Story

A TC title is always prefixed by the User Story key in every modality. Test Set membership is an issue link — never the prefix.

4 · @atc = the Jira key

The decorator carries the TC's own Jira key as a string literal: @atc('PROJ-101'). No synthetic IDs, no template literals.

5 · @integration, not @api

The API-test tag is @integration — the equitable counterpart to @e2e. (The @api/ import alias is a different thing and stays.)

Layer · CASE — the most important shape in the codex

Anatomy of a Test Case title

{US_ID}: TC#: should <expected outcome> [<connector> <condition>] [given <precondition>]
{US_ID} — User Story key, always TC# — sequential (TC1, TC2…) should — fixed, verb-first <outcome> — verb + object asserted [connector] — when / if · optional [given] — scope / permission · optional

EXAMPLES

PROJ-101: TC1: should grant access when credentials are valid
PROJ-101: TC2: should reject login if password is incorrect
PROJ-101: TC3: should cap input when exceeding 50 chars
PROJ-101: TC4: should block checkout when cart is empty given a logged-in user

REJECT — vague, not the word "should"

Login test — no ID, no TC#, no outcome
Login - error — too vague
TC1: Test form — missing US_ID prefix
should work correctly — no concrete outcome

The distinction that drives the whole codex

should  vs  Validate

CASE · the leaf

should <outcome>

One concrete behavior, asserted. The thing that passes or fails.

should grant access when credentials valid

Applies to: TMS TC · ATC method intent · test() · Gherkin Scenario

GROUP · the branch

Validate <feature>

The set of cases for a capability. Names the box, not a case.

Validate user login

Applies to: Xray Test Set summary · code describe()

Together in code

describe('PROJ-101: Validate user login', () => {
  test('PROJ-101: should grant access when credentials are valid')
  test('PROJ-101: should reject login when password is wrong')
})

The ratified conventions

Twelve artifacts that had only an implicit or undefined name are now ratified conventions — written into the skills' references and enforced by convention.

12 ratified now canon lint-enforceable next

Gaps · data, evidence & architecture

Ratified · 1–6

1 · Test-data files

Fixtures in tests/data/ have no shape.

{resource}-{variant}.json → users-valid.json

2 · Evidence / screenshots

evidence/ files are ad-hoc.

{KEY}-step{NN}-{action}.png

3 · Mock / stub responses

No home or name for API mocks.

data/mocks/{endpoint}/{method}.{status}.json

4 · ADR file numbering

ADR-NNNN collides across parallel agents.

ADR-{NNNN}-{slug}.md · manual via README Index (no script)

5 · Env identifiers

Env names only implied by URLs.

local · qa · staging · production

6 · Test module folders

e2e/integration subfolders unspec'd.

{domain-plural}/ kebab-case

Gaps · reporting, runs & data models

Ratified · 7–12

7 · Allure suite labels

Reporter grouping undefined.

derive from Playwright tag — single source

8 · Test-execution files

One md file per linked execution (sync convention).

test-executions/{TESTEXEC|RETESTEXEC}-{KEY}-{slug}.md

9 · Nested defect files

One md file per linked defect (sync convention).

defects/DEFECT-{KEY}-{slug}.md

10 · Data factory / types

Faker payloads & models vary.

DataFactory.ts · types.ts · constants.ts

11 · Gherkin variables

Placeholder style implicit.

{snake_case} → {user_id}, {order_amount}

12 · Blocked-test marker

Bug-blocked tests inconsistently tagged.

@blocked:{BUG-KEY} + test.fail()

All 12 are ratified — now canon in the skills' references. Next: optional lint enforcement.
