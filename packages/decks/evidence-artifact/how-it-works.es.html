/evidence-artifact

Mientras una sesión de testing prueba, registra lo que comprueba en un evidence pack en JSON. Un comando convierte ese pack en una página HTML autocontenida y el tool de Artifact la publica: con un solo enlace, un desarrollador o un PM ve el veredicto, el build bajo prueba, los casos y los bugs, con la prueba de cada uno.

La regla de privacidad · 4 de 13

La evidencia de QA no sale de donde vive

Lo que trae una captura de QA

Datos reales de producto y de clientes, y a veces de personas: nombres, emails de contacto, teléfonos. Mandarla a un servicio externo de imágenes (subida, resize, OCR, generación, hosting) ya es una fuga, exista o no permiso en el chat.

Marcar no es lo mismo que ocultar

Un cuadro de anotación sobre un valor no lo tapa: la página sigue con los píxeles originales y cualquiera puede apagar las marcas. El build quema los cuadros de redact en los píxeles antes de codificar el JPEG, así que la página nunca guarda la copia sin tachar.

Lo que nunca entra a un pack

Tokens, cookies, headers Authorization, API keys, contraseñas, trazas, HAR, volcados de consola o de red, .auth/* o el estado del navegador. El build los rechaza y nombra el campo, nunca el valor.

Cómo construye sin salir de la máquina

El build corre en esta máquina con Python y Pillow, sin ninguna llamada de red. La evidencia solo sale por dos caminos: el artifact privado de claude.ai que comparte el dueño, y la única miniatura por bug que se embebe en el tracker.

Retención

Se borra 6 meses después de que el ticket llega a Done, por una revisión periódica donde el dueño confirma cada borrado. La sesión nunca borra sola.

references/privacy.md: "Sharing", "Masking means burning, not covering", "Never in a page", "Why everything is built locally" y "Retention".

Stage 2 · 6 de 13

Cada prueba entra al pack en el momento

La regla

Se agrega cada prueba a <PBI>/evidence/evidence-pack.json a medida que se testea. Un pack armado de memoria al final pierde lo que la pantalla mostró.

screenshot --filename -> pack: image item + marks (eval bbox, px) api / sql items -> credentials <redacted> datos personales -> cajas "redact"

Marcas exactas, no una lectura de pantalla

Las marcas salen de la caja del elemento via playwright-cli eval. Leer la captura completa para ubicar una marca es solo para cuando ningún elemento llega a esa zona: cuesta contexto en cada turno siguiente.

Un bug, su propio pack

Cuando el hallazgo se convierte en un bug con su propio issue, recibe evidence-pack-<BUG>.json, kind: "bug" y un caso repro. Esa página se construye y publica antes que la del ticket.

Lo que nunca entra

Una traza, un HAR, un token o un .auth. El build rechaza el resto y nombra el campo.

Compact Rules del SKILL.md: "Append every proof...", "Take marks from the element's box...", "A mark does not mask anything...", "Keep a trace, a HAR, a token...", "Give a bug its own pack...".

Stage 3 · build y publish · 8 de 13

Un comando construye, Artifact publica

bun run evidence build \ --pack <PBI>/evidence/evidence-pack.json

Necesita Python 3.9+ y Pillow. Valida el pack y nombra el campo si algo no cierra, quema los cuadros de redact, e inlinea cada captura a tamaño nativo en JPEG. No hace ninguna llamada de red.

Si el pack ya tiene artifact.url

Se lee esa url primero (Artifact action: "read") y se publica con ella. Omitirla crea una segunda página y deja huérfano todo enlace anterior.

El límite

El build se detiene por encima de 14 MB; el límite del artifact es 16 MB.

Sin el tool de Artifact

Se reporta la ruta del pack en vez del enlace, y el conductor publica.

Sección "Commands" y Compact Rules ("Build with bun run evidence build...", "Publish with the Artifact tool...") del SKILL.md, y su tabla de hechos ("Inline images").

Dónde queda el enlace

La ATR, la descripción del bug, el pie del comentario de QA y las notas de cada TC.

La miniatura de un bug

bun run evidence attach (--dry-run primero). Cuenta como embebida solo después de un read-back en vivo; "(image embedded below)" y --evidence-embedded van después de eso, nunca antes.

--replace necesita a una persona

Borra la miniatura anterior y no se puede deshacer. Sin ese OK, attach se rechaza solo.

Compact Rules del SKILL.md sobre record, board, link y attach; gotcha "The thumbnail counts as embedded only when a live attach printed read-back OK".

ReglaPor qué
