Agentic QA · Repo instructions

Instructions, in layers

The agent does not need every rule in the repo on every turn. It always needs the ones that bind it, and the rest when the request calls for them. That is why AGENTS.md is the core that loads in every session, each topic lives in its own file under .agents/instructions/, and a fixed router, backed by a hook, says which one to read and when.

L0: AGENTS.md L1: .agents/instructions/ Hook: ROUTE: read Gate: bun run instructions:check
Category deck: it explains a mechanism of the repo, not a skill, so there is no slash command to invoke. It covers how instructions are split between what always loads and what is read on demand, and what holds that together. Press → to advance, S for presenter mode, O for overview, F for fullscreen.

01 · Reason · 2 of 14

Why split the file

Before, AGENTS.md was a single file that every session loaded whole, needed or not. It had two costs, and the second one was not visible.

Visible cost

Every session paid for the whole file

A chat about one selector paid for the git policy, the PBI cache and every harness contract. The conditional sections always loaded, even when the session never used them.

Invisible cost

Codex cut it in the middle

Codex cuts the project instructions at the byte that crosses project_doc_max_bytes, without telling the model. Measured at the time of the split (ADR-0009): the old file was more than three times that limit and the cut landed inside §4, the context-loading map. In Codex, everything after it never reached the model.

What does work

An import shrinks nothing

In Claude Code an @file is expanded in full at startup, and neither OpenCode nor Codex expands imports. What works the same in Claude Code, OpenCode, Codex and Pi is the model reading a file because an instruction tells it to, and a hook that adds text on every request. The design uses those two things.

What Codex lost after the cut: the harness contract, the skills table, tool resolution, the variables, the PBI, KATA, git and memory. The exact numbers are in .context/ADR/ADR-0009-progressive-disclosure-of-instructions.md.

The visible cost is tokens; the invisible one is worse because nothing fails: Codex simply does not see the second half of the file and works without those rules. The limit comes from the CODEX_PROJECT_DOC_MAX_BYTES constant in scripts/lint-instructions.ts. The measurement dates from the day of the split and lives in the ADR, not in this deck.

02 · Architecture · 3 of 14

Three layers, three loading moments

The arrows are on-demand reads: L0 never imports a section. The ones in the drawing are examples; the real list is the folder.

LayerFile and when it loads
L0AGENTS.md, in every session and on every host. OpenCode, Codex and Pi load it natively; Claude Code gets it through CLAUDE.md, which is exactly @AGENTS.md plus a line break.
L1One file per topic in .agents/instructions/, on demand: the L0 router says when, and the hook reminds with a ROUTE: line.
L2The references/ of each skill, on demand, when a section or a skill names them.

Once it applies

A section binds exactly the same as AGENTS.md. Reading it on demand changes when it enters the context, not how much weight its content carries.

L0 is the only thing that always loads. L1 are the files in .agents/instructions/: besides the topic sections there are agent-project.md (the project's own), agent-project.md.template and the README. L2 existed before the split: they are each skill's references. The rule that a section binds the same as AGENTS.md is in the LOAD PROTOCOL and in .agents/instructions/README.md.

03 · Router · 4 of 14

The fixed router

A table in L0, between <!-- router:start --> and <!-- router:end -->, with four columns. The rows are request types, not features: the table does not grow with the project, the section and its triggers: do.

ColumnWhat it saysExample (git row)
When the request involvesthe request type that fires the rowgit: branch, commit, push, PR, conflict, strategy
Readthe files to read: each section by its file name in backticks, resolved under .agents/instructions/. The first one is the row's anchoragent-git.md
Wasthe § number that content had before the split, so a §N citation still resolves§11
Thenthe skill or file that loads next/git-flow-master

A single table

The hook reads this same table from disk on every request, together with each section's frontmatter. There is no generated copy: the table the model reads and the one the classifier runs cannot diverge.

Markers that cost nothing in Claude

Claude Code strips block-level HTML comments before injecting AGENTS.md, so the two markers cost the model nothing. The hook reads them from the file on disk.

The real list of rows is in AGENTS.md; this deck does not copy it, because it would change with the life of the repo. A new topic almost never adds a row: it grows an existing section and its triggers. Only a request type that no row covers justifies a new row (.agents/instructions/README.md, Editing rules).

04 · Protocol · 5 of 14

The LOAD PROTOCOL

A paragraph at the top of L0 turns the router into an obligation. Without its sentences, the table would be a suggestion.

  1. Before acting, the request is compared against the router and every matching section file that is not yet in the conversation is read.
  2. A ROUTE: line injected by the hook is binding and wins over the model's own judgment: its file is read before acting.
  3. A ROUTE-OPTIONAL: line does not bind: one of its files is read only if the task needs it.
  4. A ROUTE-PENDING: line names a binding file that is still unread: it is read before the next step.
  5. A section already read is not re-read, unless a compaction or a /clear removed it from the context.
  6. When in doubt, read. A skipped section is exactly the failure this design prevents.
  7. A section binds exactly the same as AGENTS.md.
  8. A §N citation, anywhere, names the numbered heading kept verbatim in the file the router lists for it.

The editing rule (edit the owning section, never paste its prose back into AGENTS.md) is not part of the protocol: it lives in the header of AGENTS.md and in "Editing rules" of .agents/instructions/README.md.

The sentences are verbatim from the LOAD PROTOCOL in AGENTS.md. The one saying a section binds the same as AGENTS.md is what makes on-demand reading weaken nothing. The §N citation one keeps old citations alive: §11 still points to git because the Was column of the router says where it went.

05 · Hook · 6 of 14

The hook and the ROUTE: line

The router in L0 depends on the model consulting it. The hook does not: it classifies every request with code and writes down what to read. It is the same emitter that already adds the AGENT IDENTITY: line: .agents/hooks/personality-reinject.mjs.

# one line per new file, after AGENT IDENTITY:, and after ORCA: if the binary is present ROUTE: read .agents/instructions/agent-git.md (git, <n> lines) before acting on this prompt ROUTE: read package.json (<n> lines) before acting on this prompt # what went past the cap, in a single line that does not bind ROUTE-OPTIONAL: the prompt also touches .agents/instructions/agent-harnesses.md (harnesses); read one only if the task needs it.
HostHow the line arrives
Claude CodeUserPromptSubmit runs the emitter; SessionStart compact or clear re-arms it; PostToolUse without a matcher reminds about an unread path.
CodexThe same except the reminder, and only in a trusted repository.
OpenCode 1chat.message classifies, the system transform pushes the lines, session.compacting re-arms.
OpenCode 2The session prompt hook classifies, context pushes, compaction re-arms.
PiAn extension (.pi/extensions/agentic-qa.js) instead of a command hook, and only if the project is trusted.
RuleWhat it does
AnchorA row fires when the request matches its first Read file, and then all the files in the row are routed.
TriggersEach section declares in its frontmatter triggers: (case-insensitive regex, in English; a request in another language loads by meaning, see the LOAD PROTOCOL) and paths: (repo paths the request names). Tuning the routing means editing those lists, never L0.
ScopeA ROUTE-SCOPE: line in the request replaces the request for classification: each item is a section id (routed directly) or words (classified); none routes nothing.
Ranking and capFired rows are sorted by the strength of their anchor. Only the first MAX_ROUTED_SECTIONS get a binding ROUTE:; the rest go to a single ROUTE-OPTIONAL: line that is not recorded as routed (ADR-0017).
ReminderThe first tool of the turn that reads no routed section, while some section is still unread, gets one ROUTE-PENDING: line. It is not repeated within the turn and stays quiet for subagents.
Per-session dedupeA JSON per checkout and per session, in agentic-instruction-routes/ under the system temp, remembers what was routed. A request that needs nothing new adds nothing.
Re-armAfter a compaction or a /clear, the emitter deletes that state and prints nothing: what left the context is routed again the next time it is needed.
Detail of the rules. Anchor: this way a file shared by two rows does not drag in the other row's files. Triggers: an import that anchors only its own row (@package.json) uses the emitter's IMPORT_ROW_TRIGGERS. Scope: without the ROUTE-SCOPE: line, a request with an orchestrator's preamble is classified only by the task block that follows its marker. Ranking and cap: an agent reads a single route far more reliably than one of five in the same turn. One emitter, one adapter per harness: Claude Code and Codex run it as a command hook, OpenCode imports it from .opencode/plugins/personality-reinject.js, Pi loads it from .pi/extensions/agentic-qa.js. A prompt that starts with <task-notification> (the harness notice that a background subagent finished), or that carries only harness blocks such as system-reminder, routes nothing and does not touch the routing state: nobody asked for those routes. The routing state never lives in the repo: it is session state. Codex trust is runtime state, which is why setup:doctor reports it separately (agent-harnesses.md, Codex trust).

06 · Rules · 7 of 14

Critical rules: the binding sentence in L0, the full text elsewhere

A rule that binds has to be where the agent always reads. Its rationale, edge cases and measurements do not need to take up every turn.

# each rule in L0: number, name, its verbatim sentence and the Full: pointer 7. **Quality verification**: After code changes, verify in order: tests, types, lint. Full: agent-critical-rules.md#7

In L0

The binding sentence, verbatim

Same number, same name. Each sentence is a verbatim fragment of the full text: L0 may shorten a rule, never rewrite it. What binds keeps loading in every session.

In L1

The full text, in one file

agent-critical-rules.md has each rule under ## N. Name, with the complete rule, its rationale and its measurements. The router sends the agent to read it when it is about to break a rule, is unsure, or is asked about one.

When editing

Two places, on purpose

Changing a rule means touching its text in agent-critical-rules.md and its sentence in AGENTS.md. bun run instructions:check verifies that each sentence is still verbatim and ends in Full: agent-critical-rules.md#N.

The example is rule 7 exactly as it is in AGENTS.md. The "Full: agent-critical-rules.md#7" is the pointer to the file with the complete rule, with its number. The lint compares number, name and each sentence against the heading with the same number in agent-critical-rules.md.

07 · Imports · 8 of 14

Two imports for Claude, a reinforced instruction for the others

package.json and .agents/project.yaml are the two data files consulted most. The two router rows that name them do two things at once.

# Read cell of the variables row whenever any of these apply, read @.agents/project.yaml and `agent-project-variables.md`, NEVER hardcode identity, ... # Read cell of the scripts row whenever any of these apply, read @package.json first, never a command quoted in a doc
HostWhat happens
Claude CodeThe @ goes as plain text, outside backticks: Claude Code skips imports that sit inside code, and the lint and the hook do not count them either. Both files load whole when the session starts.
OpenCode, Codex and PiThey load AGENTS.md natively, without the CLAUDE.md shim. They follow the reinforced instruction in the same row ("whenever any of these apply, read ...") and open the file when the condition is met.

Cost

In Claude Code both imports always load: they add to the session start even though they do not count against the L0 budget, which measures the bytes of AGENTS.md. The measurement is in ADR-0009. bun run instructions:check fails if an @ in a router row does not resolve from the repo root.

The anchor of the variables row is agent-project-variables.md, because sections in backticks come before imports: a request about environments loads the variables and the yaml. The scripts row has no section, so its anchor is @package.json and IMPORT_ROW_TRIGGERS fires it. On hosts with a hook, the "ROUTE: read package.json" line reinforces the same instruction.

09 · Editing · 10 of 14

How it is edited

Every edit goes through a single path: /framework-development mode instructions, which places each sentence using the doctrine in references/instructions-doctrine.md. The sections are shared doctrine: bun sync syncs them like a skill. agent-project.md belongs to the project and is never synced; a project without it receives it once from agent-project.md.template. Golden rule: the text goes to the owning file, never back to AGENTS.md.

I want to changeWhere
the detail of a topicits file in .agents/instructions/
when a section is routedits triggers: and paths: in the frontmatter
a critical ruleits text in agent-critical-rules.md and its verbatim sentence in AGENTS.md
a rule only this project has.agents/instructions/agent-project.md (or a context skill, if it is knowledge of the system under test)
a line with NEVER or MUST in a sectionkeep it reachable: verbatim sentence in L0 or in agent-critical-rules.md, or Rule #N, binding: `/<skill>`, enforced: `bun run <script>`
a ROUTER rowonly with an ADR that decides it: bun run instructions:check --accept-router ADR-NNNN and the fingerprint it prints goes into that ADR
CLAUDE.mdnothing by hand: it is the shim generated by bun run agents:compat

Gate

bun run instructions:check checks budget, stub, router, frontmatter, triggers that compile, rule sentences and that every NEVER or MUST is reachable. It also holds three locks (ADR-0013): the ROUTER locked behind an ADR, the router eval with floors for recall, for recall on the binding lines and for precision on every run, and a new section arriving complete. It runs inside bun run repo:check. The full guide is in .agents/instructions/README.md.

The golden rule is in the header of AGENTS.md and in "Editing rules" of the instructions README. The CLAUDE.md point comes from agent-harnesses.md, GENERATED vs VERSIONED: the source is edited and regenerated, and agents:compat:check fails if someone writes prose into it.

10 · Budgets · 11 of 14

L0 budgets

L0 has a ceiling because Codex cuts without warning. The values are named constants in scripts/lint-instructions.ts, the same in both boilerplates.

LevelConstantIf exceeded
Target · 20 KiBL0_TARGETwarning: the number stays in view
Ceiling · 24 KiBL0_BUDGETerror in the boilerplate's L0: the detail goes to a section
With project additions · 28 KiBL0_PROJECT_BUDGETerror in a project: its text goes to agent-project.md or a context skill
Codex cap · 32 KiBCODEX_PROJECT_DOC_MAX_BYTESalways an error, whatever the others say: it is the default value of project_doc_max_bytes

The warning is on purpose

§2 enters whole by the owner's decision (ADR-0009), so L0 can pass the target without passing the ceiling. The warning stays in view so nobody adds text to L0 without thinking. The current size and its status are printed by bun run instructions:check.

The boilerplate ceiling is meant for "the whole behavior plus the sentence of each rule", as the L0_BUDGET comment says. The real size changes with every edit, which is why this deck does not write it: the gate says it.

11 · Measurement · 12 of 14

How we measure that it works

Two different questions: whether the classifier routes what it should route, and whether the model then reads what was routed to it.

What is measuredWhere
Classifier recall and precisionHand-labeled requests in English, plus requests in Spanish that share a stem (regres, explorat), ones that share none under meaningOnly, with no score, and with QA vocabulary (shift-left, ATP and ATR, Xray, KATA, regression, PBI cache, handoff, fleets, {{VAR}}), in cli/lib/fixtures/instruction-router-eval.json. bun run instructions:check scores it on every run against its targets field, which never goes below the floors in scripts/lib/router-eval.ts (recall, recall on the binding lines and precision).
That it stays fastcli/lib/instruction-router.test.ts requires that routing a request stays well under 50 ms
That hook and lint read the samescripts/lib/hook-router-parity.test.ts ties the hook's parser to the one in scripts/lib/instructions.ts
That the real hook answersthe test launches the emitter process with a git request and expects its ROUTE: line
That the model obeysbun run instructions:audit: of the injected ROUTE: lines, how many the agent read in the same turn and how many reads followed a ROUTE-PENDING: reminder, measured on the local Claude Code transcripts (names and counts only). The results are in ADR-0013.

If it fails

A request that does not route what it should is fixed in the section's triggers:, and the request goes into the labeled set. Relabeling to hide a false positive is not a fix.

Mind the command: in this repo bun run test is Playwright; the eval runs inside instructions:check, and the timing test with Bun's runner, bun test. The measured numbers (recall, precision, time) go to the ADRs, not the deck: they change every time a request is added to the set.

Closing · 14 of 14

What changes depending on who you are

If you use the agent

Nothing: the router and the hook decide what to read, and the LOAD PROTOCOL makes the model read it before acting. In OpenCode 2 there is no routing hook, and the model follows the router on its own.

If you edit instructions

Through /framework-development mode instructions. The text goes to the owning file, never back to AGENTS.md; what is specific to the project goes to agent-project.md, and a ROUTER row needs an ADR. Before committing, bun run instructions:check.

If something does not route

Adjust the section's triggers: and add the request to cli/lib/fixtures/instruction-router-eval.json, so the eval watches it from there.

Source of truth

AGENTS.md · .agents/instructions/README.md · .agents/hooks/personality-reinject.mjs · scripts/lint-instructions.ts

End of the walkthrough. The whole idea: what binds always loads, the rest is read when the request needs it, and a hook plus a gate make sure that happens on every host.
