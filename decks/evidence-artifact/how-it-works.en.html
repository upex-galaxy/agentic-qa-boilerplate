/evidence-artifact

While a testing session tests, it records what it proves in a JSON evidence pack. One command turns that pack into a self-contained HTML page, and the Artifact tool publishes it: with one link, a developer or a PM sees the verdict, the build under test, the cases and the bugs, with the proof for each.

The privacy rule · 4 of 13

QA evidence stays where it lives

What a QA screenshot carries

Real product and customer data, sometimes personal data too: names, contact emails, phone numbers. Sending it to an external image service (upload, resize, OCR, generation, hosting) is already a leak, whatever the chat authorises.

Marking is not the same as hiding

An annotation box drawn over a value does not mask it: the page still carries the original pixels, and anyone can toggle the marks off. The build burns the redact boxes into the pixels before it encodes the JPEG, so the page never holds an untouched copy.

What never enters a pack

Tokens, cookies, Authorization headers, API keys, passwords, traces, HAR files, console or network dumps, .auth/* or browser storage state. The build refuses them and names the field, never the value.

How it builds without leaving the machine

The build runs on this machine with Python and Pillow, with no network call at all. Evidence leaves through only two doors: the private claude.ai artifact the owner shares, and the one thumbnail per bug embedded in the tracker.

Retention

Deleted 6 months after the ticket reaches Done, through a periodic review where the owner confirms each delete. The session never deletes on its own.

references/privacy.md: "Sharing", "Masking means burning, not covering", "Never in a page", "Why everything is built locally" and "Retention".

Stage 2 · 6 of 13

Every proof enters the pack in the moment

The rule

Every proof is appended to <PBI>/evidence/evidence-pack.json as testing happens. A pack rebuilt from memory at the end loses what the screen showed.

screenshot --filename -> pack: image item + marks (eval bbox, px) api / sql items -> credentials <redacted> personal data -> "redact" boxes

Exact marks, not a screen read

Marks come from the element's box via playwright-cli eval. Reading the full screenshot back to place a mark is only for when no element reaches that zone: it costs context on every later turn.

A bug gets its own pack

Once the finding becomes a bug with its own issue, it gets evidence-pack-<BUG>.json, kind: "bug", and a repro case. That page is built and published before the ticket's own page.

What never gets in

A trace, a HAR, a token or a .auth file. The build refuses the rest and names the field.

SKILL.md Compact Rules: "Append every proof...", "Take marks from the element's box...", "A mark does not mask anything...", "Keep a trace, a HAR, a token...", "Give a bug its own pack...".

Stage 3 · build and publish · 8 of 13

One command builds, Artifact publishes

bun run evidence build \ --pack <PBI>/evidence/evidence-pack.json

Needs Python 3.9+ and Pillow. It validates the pack and names the field when something does not close, burns the redact boxes, and inlines every screenshot at native size in JPEG. It makes no network call.

When the pack already has artifact.url

That url is read first (Artifact action: "read") and published with it. Leaving it out mints a second page and orphans every earlier link.

The limit

The build stops above 14 MB; the artifact's own limit is 16 MB.

With no Artifact tool

The pack path is reported instead of the link, and the conductor publishes.

SKILL.md "Commands" section and Compact Rules ("Build with bun run evidence build...", "Publish with the Artifact tool..."), and its facts table ("Inline images").

Where the link lands

The ATR, the bug description, the QA comment footer, and each TC's notes.

A bug's thumbnail

bun run evidence attach (--dry-run first). It only counts as embedded after a live read-back; "(image embedded below)" and --evidence-embedded come after that, never before.

--replace needs a person

It deletes the earlier thumbnail and cannot be undone. Without that OK, attach refuses on its own.

Safeguards · 12 of 13

What the skill never does

RuleWhy
Send a QA screenshot to an external image service, with chat permission or without itit carries real product and customer data; the build runs locally
Publish without reading the url the pack already carriesit mints a second page and orphans the earlier links
Leave a "masked" value visible in the pixelsan annotation box hides nothing; the redact is burned in before encoding
Pass a bug pack's retest round with a current DEFERRED casea bug never passes over an active deferral
Give a case PASSED or FAILED with no evidence of that roundthe verdict is derived from what was observed, never asserted
Mark a bug's thumbnail as embedded without a live read-backa --dry-run never counts as attached
Run --replace without a person's OKit deletes the earlier thumbnail and cannot be undone
Delete an artifact on its ownretention is the owner's call, ticket by ticket

Invocation and where to read more

How it is invoked

Claude Code: /evidence-artifact plus the pack or the ticket.
OpenCode and Codex: load the evidence-artifact skill.
Pi: /skill:evidence-artifact

It has no modes. The normal case is /sprint-testing loading it on its own, in Stages 2 and 3.

What it reads

The ticket's evidence/evidence-pack.json, each bug's pack, and the templates in templates/evidence-artifact.html.

What it leaves

One published page per ticket and one per bug, the url recorded in the pack and on the board, and the remote link on the issue.
