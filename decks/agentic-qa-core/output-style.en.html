How the AI writes from now on

Three layers govern every chat reply, each over a different dimension. This page shows the split and a fictional QA session rendered in both styles, so the difference is seen instead of read.

AGENTS.md §2 user instructions → ## Replies + humanizer 2026-08-17

01The layer split

Each layer rules over a single dimension. When two layers claim the same one, they contradict each other, and the one that is reinjected more times per turn wins, not the one that is right. That is why each layer has its own dimension and its own file.

LayerDimensionWhere it livesFrequency
AGENTS.md §2wins what is said, granularity and register Butler + PM Voice + Visual Mapping every turn, via the new hook
Replies how the render looks ## Replies section of the user-level instruction file, one shared ~/.agents/AGENTS.md for every harness at session start
humanizer how the prose sounds user-level humanizer skill, which the user file says to load before writing text a person will read when writing that text
Rule
§2 always wins on content. ## Replies only decides the render (headings, one bold anchor per block, backticks, tables, spacing, lists only for real lists), and humanizer only the prose (no machine tells, no em dash, no closing recap). If a rule in there ever changed what is said, it is misplaced and belongs in §2. And if a skill or a project file defines its own output format, that format wins for that turn. The user file is a single one: ~/.claude/CLAUDE.md, ~/.codex/AGENTS.md and ~/.config/opencode/AGENTS.md point to it, and Pi appends it to its generated AGENTS.md, so all four tools read the same rules.

03What was changed

Seven actions, all applied and verified with bun run repo:check.

01 · 02

WRITING STYLE became OUTPUT STYLE, and that became Replies + humanizer

First the blacklists (BANNED VOCABULARY, BANNED PHRASES, BANNED RHETORICAL PATTERNS) were replaced by a positive section, ## OUTPUT STYLE. That section and ## REDACCIÓN PARA HUMANOS no longer exist: the render now lives in ## Replies and the prose rules in the humanizer skill, which keeps the literal technical-use exception so you can write API key without dodging it.

applied
03

Butler bullet without the em dash

The canonical format goes from topic — fragment to topic: fragment. The instruction ordered an em dash while the global rule forbade it, so no correction was going to work while the example said otherwise.

applied
04

Em dash sweep

AGENTS.md and docs/ai-personality.md were swept (retired path; the page is docs/core/personalidad.html). The model imitates the typographic density it sees in its own instructions, and it saw many em dashes against one line that forbade them. The sweep on this report's date left them at zero; the current state comes from a search in the file, not from this page.

applied
05

Headline punch removed

The rule forced every reply to open with a different hook phrase each time. Manufactured theatre, and it contradicted the anti-theatre trait of the personality itself. The menu's orientation question stays: that one does help navigation.

applied
07

ai-personality.md resynced (page: docs/core/personalidad.html)

Five drift points: nonexistent hook paths, 6-component against 7-COMPONENT, /sdd-* skills that are not installed, and a description of the global file that listed things that file never had. Section 3.7 is added documenting the new layer.

applied
06

Contract reinjection hook

.agents/hooks/personality-reinject.mjs stores the text once and a thin adapter per harness registers it: .claude/settings.json, .opencode/plugins/personality-reinject.js, .codex/hooks.json and .pi/extensions/agentic-qa.js. Without it, PM Voice and Butler are read once and fade over the course of the session: the problem was mechanical, not editorial. It costs a few dozen tokens per turn.
