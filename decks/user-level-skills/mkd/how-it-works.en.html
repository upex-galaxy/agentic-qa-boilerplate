The deck model · 3 of 8

Four kinds of screen

decision

A problem in plain language, context balloons, and options that each carry a written justification. You can add your own option and a note.

question

Markdown content with a single, multi or toggle control, plus free text.

report

A section of a plan or report. You react in text and can quote exact phrases.

table

One answer per row, through a popover with controls and text.

The hard rule

Every option states what it buys and what it costs, or the validator rejects the spec (exit 2). At most one option is recommended, and its text says why. Decks usually offer 2 or 3 options, up to 5 when the paths are really different, and your own custom answer always sits on top as a sixth slot.

The interface · 4 of 8

One screen at a time, always in reach

  • Dark navy by default. The sun icon switches to a soft light theme, and the deck remembers your choice.
  • Previous, Skip for now and Next sit in a bar that never scrolls away. Next turns solid once the item has an answer.
  • Keys: 1 to 6 pick the option at that place on screen, Enter or → go on, ← goes back, S skips. None of them fire while you type.
  • The footer shows progress, how many items are still pending and a jump to the first one. Sending with items pending asks first.
  • Skipping means "decide later", never a rejection. Closing the tab loses nothing.
SKILL.md, "Deck chrome"; cli/ui/app.js (keys, action bar, confirmation).

Deciding without a nudge · 5 of 8

Shuffle, hide, same answers

Shuffle options

A button. Each press puts every decision in a new order, never the author's and never the one you just saw. Original order brings it back.

Letters follow the screen

After a shuffle, A is always the top option. The digit keys follow the same order.

Hide recommended

A switch that hides the badge and the bolded "Recommended" at the start of its justification. Off by default, remembered.

Display only

Your answer keeps the author's option key. The same answers give the same Result JSON with or without either control.

The artifact viewer

claude.ai blocks frames and remote images inside an artifact. In artifact mode a Loom or YouTube video becomes a poster card that opens in a new tab, and the CLI builds every picture into the page, so nothing remote loads.

If Claude does not answer

Send saves your answers in the artifact first, then wakes the session. If nothing happens, type any message, for example listo. The agent checks a pending deck at the start of every message and reads the saved answers.

Artifact in Orca

open-artifact <url> opens the published deck in an Orca tab next to the terminal.

The Result · 8 of 8

The JSON is the contract

{ "session": "release-review",
  "submittedAt": "2026-11-18T10:24:00Z",
  "stats": { "total": 6, "answered": 4,
    "skipped": 1, "recFollowed": 2,
    "overridden": 1, "custom": 1 },
  "items": [
    { "id": "D1", "type": "decision",
      "status": "answered", "chosen": "B",
      "chosenLabel": "Ship to everyone",
      "wasRecommended": true,
      "customText": "", "note": "after Friday" },
    { "id": "D2", "status": "skipped",
      "chosen": null, ... } ] }
  • skipped means decide later. The agent asks again, it never takes it as a no.
  • chosen: "CUSTOM" means do what customText says, or ask if it does not add up.
  • The agent reads every note, and weighs the quotes you highlighted.
  • Artifact mode stores the same object in the artifact database, under results/<session>.
