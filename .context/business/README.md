# business/ - Business Context

Home of the **constitution outputs** discovered once by `/project-discovery` Phase 1 (who/what/why).

The business maps do not live here: they are a synthesis, so each one lives inside its context skill (`.agents/skills/business-{data,api,e2e}-context/references/*-map.html`), generated by `project-context` modes `data` / `api` / `e2e` and read with `bun run context:map <slug>`. An old `business-data-map.md`, `business-feature-map.md` or `business-api-map.md` in this folder is kept, never deleted, and read by the generator as input the first time it builds the HTML map.

## How to Generate

- **Phase 1 outputs** — load `/project-discovery` and run the Phase 1 (Constitution) flow after Phase 0 (Project Onboarding). Prerequisites: `.context/project-config.md` (from Phase 0), access to source code, optional access to existing docs (Confluence/Notion).
- **Business maps** — not in this folder: run `project-context` once per mode (`/project-context data`, then `e2e`, then `api` on Claude Code; name the skill and the mode on OpenCode and Codex). They are token-heavy and best run in a clean session, in that order.

## Discovery Sources

Information here is DISCOVERED (not invented) from:

1. **Source Code Analysis** — entity/model names, module structure, comments, docstrings
2. **Database Schema** — table names, relationships, field types
3. **Existing Documentation** — READMEs, wikis, Confluence/Notion, API docs, user guides
4. **Running Product** — UI exploration with `/playwright-cli`, feature observation

## When to Read This Folder

- **Phase 2+** — before creating PRD/SRS documentation
- **Phase 5+** — before writing test cases (business context for ATPs)
- **Any QA work** — to understand domain terminology and critical flows
- **Test automation planning** — the glossary names the entities; the data map (`bun run context:map business-data-context`) is the most-referenced input for KATA work
